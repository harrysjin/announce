# 숫자 읽기·원문 숫자 대응 테스트 재현

`fix/number-reading-pdf-rendering` 브랜치에서 숫자 구현을 시작하기 전 새 회귀 테스트를 작성했다.
기준은 형태소 개선 커밋 `220baf5`이며, 기존 전체 75개 테스트가 통과한 상태다.
운영 `main`과 Render는 변경하지 않았다.

## 구현 전 실패

2026-11-08, 다음 명령을 실행했다.

```text
python3 -m unittest discover -s tests -p 'test_numbers.py' -v
Ran 1 test in 0.000s
FAILED (errors=1)
ModuleNotFoundError: No module named 'backend.numbers'
```

`test_numbers.py`에는 11개의 테스트 메서드를 먼저 작성했지만 모듈 미구현으로 import 단계에서
한 번 실패했다. 11개 동작이 개별 실행되어 실패한 것으로 세지 않는다.

이어 API·PDF 추출·이력 검증을 작성해 실행했다.

```text
python3 -m unittest discover -s tests -p 'test_numeric_api.py' -v
Ran 5 tests in 1.177s
FAILED (failures=5)
```

| 검증 | 구현 전 관찰 |
|---|---|
| 시간/백분율 원문 추출 | `10:25`가 `10`, `25`로 분리되고 `25%`가 `25`로 추출됨. |
| 숫자 읽기 선택 | 숫자 출현이 일괄 보류되어 `numeric` 읽기 선택 정보가 없음. |
| 읽기 선택 API | 새 `/reading` 경로가 미구현되어 405 반환. |
| 잘못된 읽기 ID | 서버가 제공한 선택지인지 검증하는 API가 없음. |
| 숫자 원문 표시·PDF·이력 | 선택 API/메타데이터가 없어 첫 숫자 위치 및 undo/redo 검사까지 도달하지 못함. |

최초 생성한 긴 테스트 PDF의 끝부분이 페이지 폭 밖으로 나가는 문제는 fixture 글자 크기를
12pt로 줄여 수정했다. 위 실패는 수정된 PDF에서 다시 실행해 기록한 값이다.

## 검증 범위

공식 응답 fixture의 수사·관형사 품사, 한자와 발음을 대조한다. 같은 철자의 무관한 명사 발음을
숫자 읽기의 근거로 인정하지 않는다. 읽기 선택이 필요한 숫자는 자동 확정을 요구하지 않는다.

- 한자어 `2/4/5` 및 오탐 방지 `1/3/6/7/8/9`.
- `20/40/50`, `24/25/45`의 첫음절 장음과 뒤쪽 `4/5` 오탐 방지.
- 고유어 `2명/4개/5개`, 모호한 `2번/772번`.
- 연도·날짜·금액·백분율·소수·시간·전화번호의 용법 분류와 검토 상태.
- 실제 읽기의 음절과 원문 숫자 범위의 명시적 대응, 대응이 없을 때 임의 표시 금지.
- 사용자 읽기 선택, 재분석·이력 복원, 원본 숫자 글자/좌표/PDF 원문 보존.

이 테스트는 통제된 개발용 회귀이며 일반 숫자 문맥의 독립 정확도 평가가 아니다.
최종 실행 결과는 구현이 완료된 뒤 덧붙인다.

## 의도한 기존 계약 변경

기존 `test_analysis.py`의 숫자 제외 테스트는 사전을 전혀 조회하지 않는다는
`queries == []` 조건을 검사했다. 이번 요청은 이 제외를 해제하는 기능이므로 이 조건은
읽기 후보 생성과 공식 발음 조회가 발생한다는 검사로 최소 변경했다. 기존의 원문
`0.35초` 추출 유지, 근거가 없는 테스트 응답에서 미확정 유지, 임의 장음 원 없음이라는
안전 조건은 유지한다. 사용자 수동 표시 보존 테스트도 유지한다.

실제 공식 fixture에서 `두`와 `네` 관형사는 각각 `[두ː]`, `[네ː]`, `다섯`은 `[다섣]`임을
확인했다. 따라서 `2명/4개`의 긍정 장음과 `5개`의 오탐 방지를 별도로 검사한다.
`20/40/50`의 한국어 읽기는 직접 등재된 `이십/사십/오십`을 먼저 사용하며,
`24/25/45`는 구성 수사의 첫음절 규칙 결과와 구별한다.

두 가지 원문 대응 안전 조건도 보강했다. 하나의 장음 음절이 여러 숫자에 대응하거나,
두 자리 숫자 범위 전체를 근거 없이 한 음절의 정확한 위치라고 표시한 경우에는
원 위치를 임의로 선택하지 않고 미확정이어야 한다. 이 보강 후 숫자 모듈 테스트는
12개 메서드다.

숫자 내보내기 테스트를 구현 전에 별도로 실행했다.

```text
python3 -m unittest discover -s tests -p 'test_numeric_api.py' -k numeric_exports -v
Ran 1 test in 0.017s
FAILED (failures=1)
```

기존 검증 기록에 `숫자 읽기와 원문 대응` 표가 없고, 숫자 범위 `[0:1]`이
빈 문자열의 `1음절`로 설명되는 문제를 재현했다. 이 테스트는 명시적으로 만든
메타데이터 구조로 내보내기 형식만 격리한다. 공식 사전이 전체 표현의 발음을
직접 제시했다고 주장하는 자료가 아니다. API·추출·내보내기 테스트는 현재 6개다.

## 최종 통합 실행

2026-11-09 최종 코드에서 전체 129개 회귀가 통과했다. 숫자 모듈 12개,
독립 숫자 경계 17개, 숫자 API 6개와 PDF 렌더링 17개를 포함한다.
쉼표·콜론의 일반 단어 경계 회귀와 날짜별 공식 평가 보충 자료의 계약도 테스트를 먼저 기록했다.
브라우저는 숫자·형태소·키 없는 기본 기능을 각각 통과했으며 실제 PDF 뷰어 검사는
`docs/pdf-rendering-2026-11-09.md`에 구분하여 기록했다.
