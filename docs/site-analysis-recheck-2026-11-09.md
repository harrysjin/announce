# 운영 반영·실제 문장 분석 재점검 (2026-11-09)

## 확인한 원인

두 문제가 겹쳤다.

1. 실제 운영은 아직 `main`의 `25c098bf94c33ca2884b8ffd4f14dc68a83468d2`였다.
   앞선 형태소·숫자 개선은 검토용 브랜치에만 올라가 있었다. Render 설정도 `branch: main`을 사용한다.
   운영 `/openapi.json`에 숫자 읽기 `/reading` 경로가 없고, `/api/health`는 `0.1.0`을 반환했다.
   운영 HTML의 파일은 `index-CvcIhnnx.js` / `index-DDK4do7I.css`로 수정본의 빌드와 달랐다.
2. 개선 브랜치에도 실제 문장 조합 누락이 있었다. `보도부를`은 원형을 찾더라도 명사+조사 규칙이
   없어 표시하지 못했고, `2명을`·`4개를`·`2026년에는`은 단위와 조사를 분리하지 못했다.
   `2 명`처럼 띄어 쓴 단위도 해당 숫자의 읽기에 사용하지 못했다. 이전 단독형 중심 검증이 이 누락을 놓쳤다.

운영에 생성한 짧은 진단 PDF를 올려 실제 현상을 재현했다. `보도부`만 직접 장음이 표시됐고,
`선발하며`는 기본형을 복원하지 못한 `not_found`, `2명`·`4개`·`24` 및 조사 결합 숫자는
`reading_required`였다. 해당 진단 작업은 결과 기록 후 삭제했다. 이 진단은 배포 변경이 아니다.

## 이번 수정

|파일|수정|
|---|---|
|backend/linguistics.py|연속된 명사 전체+문자 그대로의 J* 조사 경계를 복원하고 공식 명사 품사·발음을 확인해 규칙 적용. 전체 단어 직접 발음과 충돌하는 뜻은 우선 보류. 뒤 문맥 형태소·원문 상대 좌표도 재사용.|

|backend/main.py·release.py|기존 Kiwi 계획을 숫자 분석에 전달. health에 엔진 기능·버전·검증된 SHA를 제공하여 구버전과 수정본을 구별. 비밀값이나 잘못된 커밋 문자열은 노출하지 않음.|
|backend/pdf.py·src|숫자 범위 밖 단위를 실제 숫자 자리처럼 표시하지 않고 ‘뒤 문맥’으로 설명. 화면에 엔진 버전 표시. 원문·glyph 좌표와 출력 경로 유지.|
|새 회귀·브라우저·실사전 스크립트|실제 문장, 띄어쓰기, 반복 숫자별 문맥, 출처·원문·수정 이력과 배포 식별 검사.|

명사 유지 규칙은 품사가 명사/의존 명사로 확인되고 모든 허용 후보의 장단이 일치하며,
명사와 조사가 원문에 그대로 연속된 경우만 사용한다. `말의`·`말을`의 상충은 계속 보류하고,
`기쁨 씨` 호칭 보호와 임의 고유명사 접두어 금지를 유지한다. NNP 자체가 일반적인 의미 구별의 해결책은 아니다.

숫자도 `4개구리`·`4개발`·`2명예`를 4개/2명으로 잘라 해석하지 않는다.
띄어 쓴 단위는 외부 문맥 좌표를 별도로 보존하며, 숫자 안에는 길이 0·exact=false로 연결한다.
단위 글자가 숫자 표기 안에 있는 것처럼 가짜 위치를 만들지 않고, 원은 숫자에 정확히 대응하는 음절에만 표시한다.

- 띄어 쓴 단위: 숫자별 인접 문맥을 구분하지 못하는 4개 양성 하위 사례와 구두점 경계 실패를 먼저 재현했다.
- 화면·기록: 외부 단위가 `(2–1번째 글자)` 또는 빈 `원문 [1:1]`처럼 표시되는 오류를 먼저 재현했다.

### 실제 문장 브라우저 흐름

공식 응답을 재생하는 로컬 서버와 Chromium으로 실행했다. 43개 출현의 자연 문장 PDF를 올리고
후보 기록 118건(반복 포함)을 원 자료와 대조했다. 초기 7개 표시 → 뜻/읽기 선택 후 9개 → 직접 추가 후
10개 표시를 확인했다. 읽기·뜻 선택과 실행 취소/재실행, 숫자 이동·직접 추가·재분석·새로고침,
데스크톱/390px 모바일, 버전 표기, 원문 글자·폰트·좌표·기존 링크/주석, PNG/PDF 일치를 확인했다.
JavaScript 오류와 외부 브라우저 요청은 0이었다. 재분석의 자동 표시 ID 재발급은 허용하되
모든 사용자 표시 ID/상태와 모든 표시의 실제 위치·출처는 그대로 유지되는지 비교했다.

```sh
npm run build
python3 -m unittest discover -s tests -q
python3 tests/site_sentence_browser.py
# 실제 공식 API 요청에 동의하는 명시적 실행. 운영 사이트를 변경하지 않음.
python3 tests/site_live_dictionary_simulation.py --live
python3 tests/evaluation.py --strict
```

최종 전체 회귀는 **158개 통과**, 빌드와 새 문장 브라우저 및 기존 형태소/숫자 브라우저 회귀도 통과했다.
사용자 PDF나 키를 테스트 자료로 넣지 않았다. 스크린샷·PDF·JSON은 Git에서 제외된 `test-results/re-audit/`에 있다.

이전 평가에서 낭독을·기쁨을은 ‘조사 결합 규칙 미확인’ 사유로 보류를 요구했으므로 새 규칙 추가 후
그대로 실행하면 2건의 계약 차이가 발생했다. 이전 파일은 보존하고 이 두 항목만 새 명사/J 경계 근거로
갱신한 버전을 기본 평가로 사용한다. 27개 표적에서 오탐 0, 요구 보류 9/9, 정답 18개 중 14개 판정,
누락 장음 2개가 남는다. 정답/보류 분모가 달라 이전 백분율과 단순 비교하지 않는다.

## 배포 확인과 남은 범위

수정본 health는 `version=0.2.0`, `engine_version=2026.11.09.2`, `particle_boundaries` 등의
기능 목록을 반환한다. Render가 제공한 `RENDER_GIT_COMMIT` 또는 명시적 `BUILD_COMMIT`의
40자리 SHA만 공개하고, 없는 경우 null로 알려 준다. 화면에도 엔진 버전을 표시한다.

현재 운영 main/Render는 이전 지시의 검증 조건에 따라 아직 변경하지 않았다.
운영 반영 시에는 해당 커밋으로 배포된 것을 health/정적 자산으로 확인한 다음
동일 생성 대본의 업로드→분석→읽기/뜻 선택→다운로드→삭제까지 다시 실행해야 한다.
배포 시 메모리 내 임시 작업은 사라진다.

macOS Preview·Adobe Reader 실검증과 규범 전체 예외의 원문 대조는 여전히 미완료다.
소수·전화번호·날짜의 실제 읽기 경계, 호칭 없는 인명/보통명사 의미 구별, 지원하지 않는 단위·문법도
근거가 부족하면 보류한다. 모든 대본을 완전 자동 판정한다고 주장하지 않는다.
