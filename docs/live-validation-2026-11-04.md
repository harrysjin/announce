# 실제 사전 연결·PDF 분석 검증

검증일: 2026-11-04 (한국 시간). 환경 게시나 외부 사이트 배포는 수행하지 않았습니다.
인증키 값·길이·일부 문자·해시는 기록하지 않았습니다.

## 실행 환경과 연결

- 현재 실행 환경의 STDICT_API_KEY 바인딩: ready, 프로세스 변수 존재 확인.
- stdict.korean.go.kr HTTPS 허용 정책: enforced.
- 실제 공식 검색(search.do)·상세(view.do) 응답으로 표제어·의미·발음·한자를 확인.
- 인증키는 서버와 기존 프록시를 통해 사용. TLS 검증 유지.

## 실제 예시 대본 전체 시험

앱에서 제공하는 1페이지 예시 PDF를 API로 업로드하고 분석 진행 상태를 조회했습니다.
실제 사전 응답만 사용했으며, 고정 장음 목록이나 합성 발음으로 대체하지 않았습니다.

| 항목 | 결과 |
| --- | --- |
| 전체 조회 대상 표현 / 원문 출현 | 52 / 52 |
| 완료한 조회 대상 | 52 |
| 최종 조회 실패 | 0 |
| 자동 장음 확정 / 표시 음절 | 1 / 1 |

미확정 사유는 동형어·다의어 28, 실제 활용 발음 미확인 3, 정확한 표제어 미발견 18,
발음 정보 불명확 1, 조사 결합형과 표제어의 중의성 1입니다. 이는 일반적인 정확도나
재현율 측정 결과가 아닙니다. 51개 표현을 단음으로 판정했다는 뜻도 아닙니다.

자동 표시는 [표준국어대사전 ‘천천히’](https://stdict.korean.go.kr/search/searchView.do?word_no=317664&searchKeywordTo=3)의 직접 발음 근거에 연결됩니다.

- PDF·Markdown 검증 기록·CSV 다운로드 성공.
- 출력 PDF를 다시 열어 텍스트·페이지 수·MediaBox/CropBox·회전 동일 확인.
- 검색 가능한 원문 유지, 테두리 없는 #CEE4F5 원형 1개, 검증 기록 첨부 확인.
- 원본과 결과를 렌더링해 첫 ‘천’ 위의 원형 위치·글자 가림·색상을 직접 확인.
- 색상을 #F2D4DC, 불투명도 55%, 크기 105%로 바꿔 PDF에 반영됨을 확인한 뒤 복원.
- 설정 변경 시 사전 분석 상태와 어휘·근거 데이터를 재사용함을 확인.

결과물: `test-results/live-analysis/` (원본·결과 PDF, MD, CSV, 원문/결과 PNG, 요약 JSON).

## 실제 브라우저 시험

생성한 5행 PDF: `천천히 / 낭독 / 눈 / 4개 / 0.35초`.

- Chromium 1440×1050에서 실제 업로드 → 분석 → 진행 조회 → 결과 표시 성공.
- 천천히: 공식 ‘천ː천히’ 근거로 첫 음절 자동 표시.
- 낭독: 狼毒·朗讀 등 여러 후보가 실제로 반환됨. 자동 선택하지 않고 미확정 유지.
- 눈: 동형어 후보가 여럿이므로 미확정 유지.
- 4개·0.35초: 실제 읽기 확인 대상으로 미확정 유지. 소수 일부를 별도 장음으로 표시하지 않음.
- 시험 사용자가 朗讀 / ‘글을 소리 내어 읽음.’ 의미를 직접 선택하면 ‘낭ː독’ 근거로 첫 ‘낭’ 표시.
- 이 의미 선택은 사용자 선택으로 기록됨. 일반 문맥 자동 선택 성공으로 간주하지 않음.
- 다운로드한 PDF에 ‘천’과 ‘낭’의 원형 2개, 원문 텍스트와 검증 기록 유지.
- 390×844 모바일 검토 화면에서 가로 넘침 없음. JavaScript 실행 오류 없음.
- 출력 PDF와 데스크톱·모바일 화면을 직접 확인.

결과물: `test-results/live-browser/` (실제 결과 JSON, PDF, 렌더링 PNG, 화면 캡처).

## 시험 중 발견·수정한 문제

1. 최초 전체 시험에서 ‘표시를’ 조회가 일시적으로 실패했습니다. 별도 실제 조회에서는 정상적인 결과 없음 응답이 돌아왔습니다. 일시적인 네트워크 오류 및 502/503/504에만 읽기 요청을 한 번 재시도하도록 보완했습니다. 인증·정책 거절, 잘못된 사전 응답은 재시도하지 않습니다. 보완 후 전체 시험에서 조회 실패 0건입니다.
2. ‘말의 길이’의 ‘말의’를 별도 표제어 末意로 자동 판정할 수 있었습니다. 표면 형태와 조사 결합형 후보가 공존하면 자동 확정을 막고 문맥 검토 대상으로 남기도록 수정했습니다. 한 음절 기본형(눈+이 등) 후보가 누락되지 않도록 탐색 조건도 보완했습니다. 이는 전체 형태소 분석이나 문맥 자동 판정을 구현했다는 뜻이 아닙니다.
3. 브라우저 시험의 최초 가정에서 ‘낭독’을 단일 의미라고 예상했으나 실제 사전에는 여러 동형어가 있었습니다. 사전 응답에 맞춰 자동 선택 금지와 사용자 의미 선택을 검증하도록 시험을 수정했습니다. 앱이 첫 결과를 자동 선택하도록 바꾸지 않았습니다.

관련 회귀 검사를 추가한 뒤 `python3 -m unittest discover -s tests -v`의 **27개 검사 모두 통과**.
실제 연결 시험은 기본 회귀 검사와 별도로 실행합니다.

## 남은 한계

현재는 단일 의미와 실제 발음 형태가 직접 맞는 경우에만 자동 확정하는 보수적인 처리입니다.
자연스러운 대본 대부분을 완전 자동 검증하는 단계는 아닙니다. 동형어의 문맥 선택,
조사·활용형 처리, 숫자 읽기, 고유명사와 복합어, 줄·페이지 경계의 어휘 연결을 보완해야 합니다.
OCR과 일반적인 언어 판정 정확도, macOS 미리보기·Acrobat Reader 호환성은 이번 시험 범위에 포함하지 않았습니다.
