## 숫자 결과

숫자의 값별 장음 정답을 코드에 넣지 않았다. 철자·자릿값·단위별 읽기를 생성하고,
품사·한자·뜻이 맞는 공식 사전의 발음과 원문 위치 대응을 검증한다.
직접 사전 발음은 `numeric_dictionary`, 미등재 복합 수사의 첫음절 범위는
`numeric_rule`, 사용자의 읽기 선택은 별도 `choice_source=user`로 기록한다.

|사례|최종 동작|
|---|---|
|2·4·5|단독 표기는 여러 읽기가 있어 선택 대기. 한자어를 고르면 이·사·오의 공식 장음으로 해당 숫자 표시.|
|1·3·6·7·8·9|한자어 읽기를 선택해도 장음 원 없음.|
|20·40·50|한자어 읽기의 직접 등재 이십·사십·오십 발음으로 첫 숫자만 표시.|
|24·25·45|선택한 복합 수사의 첫음절 장음을 규칙으로 판단. 뒤 숫자 4·5에는 기본형 장음을 복사하지 않음.|
|2명·4개·5개|고유어 두·네의 장음은 공식 관형사 근거로 표시. 다섯은 단음으로 원 없음.|
|2번·772번|횟수·번호·식별자 읽기를 구분하고 사용자가 선택. 모호한 줄 전체 단서로 자동 확정하지 않음.|
|2026년|이천이십육 년의 공식 구성 요소와 첫음절 규칙으로 원문 첫 2 표시.|
|0.35초·10:25·전화번호|소수·시각·각 자리 읽기 후보와 원문 대응을 기록. 실제 낭독 경계·장음 또는 일대일 위치가 불명확하면 선택 후에도 미확정.|

금액의 현대 원을 옛 원/일본 엔 뜻과 혼동하지 않으며, 분은 시간과 사람 수의 읽기를 구분한다.
쉼표와 콜론이 일반 문장이나 숫자 목록의 단어 경계를 삼키는 회귀도 수정했다.
`10`의 열처럼 한 음절이 여러 숫자에 대응하거나 월 이름·어형·단위의 근거가 부족한 경우
임의의 숫자에 표시하지 않는다. 상세 범위와 실제 출처는 [숫자 근거](number-reading-evidence.md)에 있다.

## PDF 원인과 방식

기존 Circle 주석은 글자 위에서 합성되며 Multiply에 의존했다. 이를 Normal로 처리하는
재현에서 글자 내부가 회청색으로 바뀌었다. macOS Preview 자체를 이 환경에서 실행하지 않았으므로
그 뷰어의 실제 원인을 확정한 결과로 제시하지 않는다.

표시는 공통 벡터 경로로 이동했다. 일반 페이지는 원문 뒤에 원을 그리고, 불투명 배경이
원을 가리는 경우 원문 잉크를 제외하는 벡터 클립을 쓴다. 원본 픽셀은 마스크 분석에만 쓰며
출력 PDF에 페이지 이미지나 다시 쓴 텍스트를 넣지 않는다. 자동·수동·사용자 수정 모두 같은
출력 함수를 사용하고 기존 좌표·색·크기·불투명도 설정을 유지한다.

웹 화면도 같은 PDF 출력의 PNG를 표시한다. SVG는 투명 선택 영역이므로 글자 위에 원을
다시 칠하지 않는다. 출처는 비시각 Circle 주석과 링크·첨부 기록에 남긴다.
미리보기는 요청한 페이지만 처리하여 전체 문서 반복 렌더링을 피한다.

실제 적용 방식 비교, 작은 배율/복잡한 배경의 한계, 뷰어 결과는
[PDF 렌더링 보고서](pdf-rendering-2026-11-09.md)에 있다.

## 수정 전후 테스트

- 이전 형태소 작업은 기존 49개에서 실패를 먼저 재현한 뒤 75개 전부 통과하여 별도 커밋했다.
- 숫자 구현 전 모듈 미구현 import 실패 1건과 API 5개 실패를 먼저 기록했다. 렌더링은 초기 6개 중 3개 실패를 먼저 재현했다.
- 경계 검토에서 새 숫자 12개 메서드의 16개 실패 사건(하위 사례 포함)을 먼저 재현했다. 이후 17개 경계 회귀로 보강했다.
- 엄격한 잉크 검사에서 최초 31개 가장자리 픽셀 변경과 숫자 원 이동 후 잘못된 출처 배지를 먼저 재현하고 수정했다.
- 최종 `python3 -m unittest discover -s tests -q`: **129개 통과**. 기존 Starlette/httpx deprecation warning은 남아 있다.
- 최종 `npm run build`, 숫자 브라우저·기존 형태소 브라우저·키 없는 smoke: 통과. 다섯 내보내기에서 웹 PNG와 PDF 렌더가 일치하고 해당 불투명 배경 fixture의 원래 비백색 픽셀 변경은 모두 0이었다.
- 실제 Chrome PDF 뷰어 11파일 및 MuPDF 비교 실행: 검정·색상 글자 내부 픽셀 변경 0. macOS Preview와 Adobe Reader는 **미실행**이다.
- `python3 tests/evaluation.py --strict`: 기존 27개 문맥에 새 숫자 근거를 명시한 버전에서 오탐 0, 요구 보류 11/11, 길이 정답 16개 중 12개 판정. 누락 장음 2개는 남아 있다.

옛 평가를 새 기능에 그대로 실행하면 네·십일·이천이십육의 조회 자료가 없어 실패했다.
실제 공식 조회/상세 결과를 보충하고, `4개`·`2026년` 두 항목만 미검증 보류에서 공식 근거가 있는
장음으로 갱신했다. 원본 `audited_corpus.json`은 수정하지 않았다. 정답/보류 분모가 달라졌으므로
이전 14/13 결과와 백분율을 일반 정확도 개선처럼 비교하지 않는다.

## 남은 검증

달력 월 이름, 소수·전화번호·콜론의 실제 낭독 경계, 부호·지수·분수·지원하지 않는 통화와 단위,
숫자와 음절의 다대다 대응은 보류한다. 규범 원문 호스트의 환경 접근 제한 때문에 제6·7항 전체
예외의 원문 대조도 아직 완료하지 않았다. macOS Preview·Adobe Reader의 최종 실제 호환성과
동시 사용자 부하 검사는 별도로 남는다. 실제 운영에 병합·배포하지 않았다.
